# 작전 보상·저장·재접속 흐름

상태: 성장 경제와 SC2 Bank 조사에 연결한 설계 제안입니다. 정산 규칙과 저장 실패 대응을 먼저 명확히 하며, 실제 게임에 구현되었거나 안정성이 검증됐다는 뜻은 아닙니다. 구현 범위는 현재 작은 아레나 기획과 별개입니다.

## 핵심 원칙

- 캐릭터 성장은 플레이어 개인 기록입니다. 파티 전리품을 나누거나 막타를 경쟁하지 않고, 보상 자격이 있는 각 플레이어의 프로필에 각각 지급합니다.
- 작전의 기본 보상은 주 목표를 성공적으로 끝냈을 때 한 번 지급합니다. 적 처치마다 XP를 쌓지 않습니다.
- 첫 완수/선택 목표 여부는 파티 공용 표시와 별도로 **각 플레이어의 저장 기록**에서 확인합니다. 처음 온 친구와 이미 완료한 친구가 함께 출격해도 각자의 보상이 맞게 계산됩니다.
- 실패·중도 철수에는 완료 보상을 주지 않지만, 실패 벌점이나 보유 성장 손실도 없습니다. 이미 저장된 레벨·진급·구매·훈련 투자는 유지합니다.
- 저장은 완료 정산 같은 의미 있는 시점에 묶어 실행하고, 적 처치마다 기록하지 않습니다. Bank 저장이 확인되지 않으면 성공 저장이라고 알리지 않습니다.
- Bank는 기기 간 클라우드 계정 저장으로 간주하지 않습니다. 이 한계와 기존 기술 조사 내용은 [SC2 Bank 조사](../../../research/sc2/persistent-data.md)에 정리했습니다.

## 작전 시작 전: 읽기와 준비

| 순서 | 처리 | 실패 시 규칙 |
|---|---|---|
| 1 | 플레이어별 Bank를 읽고 로드 완료를 기다림 | 로드 중에는 레벨/재화를 기본값으로 덮어쓰지 않음 |
| 2 | 스키마 버전, 필수 키, 범위, 완료 기록 형식을 확인 | 유효하지 않은 기존 파일을 새 프로필로 조용히 바꾸지 않음 |
| 3 | 지원 버전이면 메모리에서 변환하고 누락 가능한 새 키에는 정한 기본값 적용 | 변환이 실패하면 원본을 보존하고 저장 없는 계속 진행 또는 출격 보류 중 안전한 경로를 택함. 저장 가능한 것처럼 표시하지 않음 |
| 4 | 각 플레이어 프로필의 지역·작전 첫 완수 여부를 읽고 이번 출격의 참가/보상 상태를 기록 | 아직 로드되지 않은 프로필을 근거 없이 신규 프로필로 취급하지 않음 |
| 5 | 파티가 출격하고 공용 작전 상태와 플레이어별 보상 상태를 분리해 추적 | 파티 진행 기록이 개인의 첫 완수 기록을 대신하지 않음 |

빈 Bank는 신규 프로필일 수 있지만, 빈 값과 읽기 실패를 구분해야 합니다. 새 프로필 기본값을 기록할 경우에도 값 검증 후에만 초기화 저장을 진행합니다.

## 작전 중: 임시 진행과 영구 변화

현재 보상 설계는 적 처치 XP가 아니라 완료 시점의 작전 보상을 기본으로 합니다. 작전 중 선택 목표 달성 여부와 참가 상태는 임시 상태로 기록하고, 주 목표가 끝나기 전에는 완료/첫 완수 플래그를 확정하지 않습니다.

레벨업·진급·훈련 투자·군수 자원 구매가 로비나 출격 전 정비 구간에서 발생한다면, 각 구매/진급은 유효성 검사 후 개인 프로필에 반영하고 저장합니다. 출격 중에 이를 허용할지는 아직 별도 결정 사항입니다. 허용한다면 UI 구현에 앞서 구매 직후 저장과 작전 보상 정산이 같은 재화를 동시에 수정하는 경우를 시험해야 합니다.

## 정산: 자격 판정과 계산 순서

1. 주 목표 성공 이벤트가 한 출격에서 한 번만 처리되도록 잠급니다.
2. 최종 정산 시점의 참가 자격을 확인합니다. 시작 로딩을 마친 뒤 작전 진행에 참여했고 정산 때 연결된 플레이어를 기본 자격으로 제안합니다. 막타/피해량 점수는 자격 조건으로 쓰지 않습니다. 세부 참여 시간 기준은 정상 협동 테스트 전에는 확정하지 않습니다.
3. 각 자격 플레이어에 대해 기본 보상, 선택 목표 보상, 그 플레이어의 작전별 첫 완수 보상을 따로 계산합니다.
4. XP/공적/군수 자원에 각각 상한 처리를 하고, 개인 프로필의 누적 수치와 완료 기록을 함께 갱신합니다.
5. 플레이어별 변경 묶음을 저장하고, 저장 결과가 확인된 범위만 저장 완료로 표시합니다.
6. 보상을 이미 적용한 출격은 메모리의 정산 잠금으로 다시 적용하지 않습니다. 완료 화면을 다시 열거나 게임 내 종료 이벤트가 중복되어도 중복 지급하지 않아야 합니다. 게임/맵이 재시작된 뒤에도 같은 정산을 판별할 안정적인 출격 ID가 가능한지는 별도 확인이 필요합니다.

완료 기여는 파티가 공유하되 첫 완수/선택 목표 기록은 개인별로 판정합니다. 예를 들어 파티장이나 기존 멤버가 이미 완료한 작전을 신규 플레이어가 함께 성공하면, 신규 플레이어는 개인 첫 완수 보너스를 받고 기존 완료자는 반복 보상을 받습니다. 파티 인원수로 재화를 나누지 않습니다.

## 보상 산식과 예시

작전 보상표의 기준은 [성장·보상 밸런스 초안](growth-economy-balance.md)과 같습니다.

```text
정산 XP = 기본 XP + 선택 목표 보너스(+기본 XP의 20%) + 개인 첫 완수 보너스(+기본 XP의 50%)
정산 공적 = 기본 공적 + 선택 목표(+10) + 개인 첫 완수(+25)
정산 군수 자원 = 기본 자원 + 선택 목표(+10) + 개인 첫 완수(+20)
```

지역 1 작전 하나의 예:

| 개인 기록/완수 조건 | XP | 공적 | 군수 자원 |
|---|---:|---:|---:|
| 반복 완수, 선택 목표 미완료 | 110 | 40 | 20 |
| 반복 완수, 선택 목표 완료 | 132 | 50 | 30 |
| 개인 첫 완수, 선택 목표 미완료 | 165 | 65 | 40 |
| 개인 첫 완수와 선택 목표 모두 완료 | 187 | 75 | 50 |

다섯 작전을 모두 첫 완수하고 선택 목표도 끝내면 개인 누적은 935 XP, 375 공적, 250 군수 자원입니다. 두 명이 함께 성공해도 각자의 첫 완수 상태가 다르면 각자 다른 행을 적용합니다. 만렙 250에서는 XP 레벨/기본 스탯 상승을 멈추며 초과 XP를 공적이나 군수 자원으로 바꾸지 않는 안을 권합니다. 계급과 강화 최대치 이후 남은 공적/군수 자원은 손실 없이 보유하고 새 소비처를 임의로 만들지 않습니다.

## 성공·실패·이탈·저장 오류

| 상황 | 지급/저장 규칙 |
|---|---|
| 주 목표 성공 | 자격이 있는 각 플레이어에게 개인 기준으로 기본 보상 지급; 선택 목표/첫 완수는 조건별 추가 |
| 선택 목표만 성공하고 주 목표 실패 | 작전 완료 보상과 첫 완수는 지급하지 않음. 체크포인트 보상은 현재 안에 없음 |
| 플레이어 사망 후 파티가 성공 | 부활/관전 등으로 최종 정산 때 참가 자격을 유지하면 동일 보상. 사망 벌점 없음 |
| 플레이어가 정산 전에 나감/연결 끊김 | 해당 플레이어의 미정산 보상을 보장한다고 약속하지 않음. 로컬 Bank에 쓰지 못한 정산을 다른 플레이어가 대신 저장하지 않음 |
| 정산이 중복 호출됨 | 출격당 메모리 정산 잠금으로 두 번째 적용 차단; 개인 첫 완수 기록도 재사용 |
| 저장 오류/확인 불가 | 플레이 진행 결과와 저장 성공 표시를 구분. 재시도하고도 실패하면 미저장 상태를 알리며, 같은 프로필의 새 영구 거래/출격을 저장 성공으로 처리하지 않음 |
| 작전 실패/철수 | 완료 보상 없음, 재화 회수/레벨 하락 없음. 실패 전 이미 저장된 성장과 정비 구매는 유지 |

재접속 도중 같은 작전에 다시 들어왔을 때 이어하기/새 출격으로 처리할지는 첫 버전에서 별도 이어하기 시스템을 만들지 않는 방향을 제안합니다. 새 출격으로 재시도하되 이전 출격의 미완료 목표는 정산하지 않습니다. SC2의 실제 연결 복구와 Bank 동작은 플랫폼 검증이 필요합니다.

## 저장 데이터와 갱신 단위

| 데이터 묶음 | 예시 항목 | 저장 시점 제안 |
|---|---|---|
| Profile | 스키마 버전, 누적 XP(레벨은 파생), 최고 레벨 기록 | 신규 프로필 생성/작전 정산 |
| Career | 현재 계급, 공적, 진급 이력 | 진급 직후 및 작전 정산 |
| Arsenal | 군수 자원, 공격/체력 강화 단계 | 구매 직후 및 작전 정산 |
| Training | 사용 포인트/노드 단계/진화 선택(누적·잔여 포인트는 레벨과 투자에서 계산) | 투자 직후 및 작전 정산 |
| Progress | 지역/작전 해금, 작전별 첫 완수, 선택 목표/발견 기록 | 정산 시 완료 보상과 같은 변경 묶음 |
| Receipt | 최근 정산 출격 식별자 또는 기록 | 보상 변경 묶음과 함께 저장; Bank에서 원자적 기록인지 테스트 필요 |

가능하면 계산된 새 프로필 상태를 전부 검증한 뒤 Bank 값을 갱신하고 저장합니다. 보상 잔액만 먼저 쓰고 첫 완수 키를 나중에 쓰는 식으로 단계별 부분 갱신을 하지 않습니다. 다만 이것이 파일 수준의 원자적 트랜잭션을 보장한다는 뜻은 아니며, Bank API의 저장 성공/백업/복구 경계는 별도로 확인합니다. 안정적인 출격 ID와 중복 정산 복구가 검증되기 전까지는 메모리 잠금이 같은 실행 안의 중복 호출만 막습니다. 프로세스 중단 시점에 따라 반복 보상이 재지급되거나 최종 저장이 빠질 가능성은 실제 Bank 샘플에서 시험할 미해결 위험입니다. 매 적 처치마다 쓰지 않고, 작전 정산·진급·구매·훈련 투자처럼 중요한 경계에서 저장합니다.

파일 형식이 바뀌면 `schemaVersion`을 올립니다. 이전 버전은 별도의 순서 있는 변환 규칙으로 새 메모리 상태를 만들고, 검증이 끝난 뒤 저장합니다. 모르는 미래 버전이나 잘못된 값은 범위 밖 값을 임의로 최대치로 올리거나 전체 프로필을 지우지 않고, 원본 보존/지원 불가 상태로 처리합니다. 필드 상한은 실제 게임 설계의 상한(레벨 250, 계급 대장, 강화 10단계, 훈련 포인트 50 등)과 맞춥니다.

## 저장 확인 메시지 원칙

새 UI 레이아웃은 제안하지 않습니다. 바닐라 SC2에서 가능한 기존 표시/메시지 수단을 먼저 확인합니다.

- `저장 완료`: Bank 저장을 확인한 뒤에만 표시.
- `저장 확인 실패`: 재시도/출격 종료 후 주의가 필요할 때 실제 상태를 구분해 표시.
- 저장 상태를 표시할 수단이 구현되지 않았다면 저장 성공을 화면 문구나 사운드로 암시하지 않음.
- 다른 PC에서도 자동 복구, Blizzard 계정에 백업, Bank 변조 방지 같은 보장은 문서·게임 안내에 넣지 않음.

## 제작 전 검증 시나리오

| 시험 | 통과 기준 |
|---|---|
| 신규 프로필로 솔로 성공 | 기본값에서 한 번 정산; 보상/완료 기록이 다음 세션에 각각 한 번만 로드됨 |
| 같은 작전 반복 | 첫 완수 보너스 재지급 없음; 기본/선택 보상은 계속 지급 |
| 2인 중 한 명만 첫 완수 | 각자의 Bank/Profile 상태에 맞는 다른 보상 합계 |
| 2~4인 동시 완료 | 보상 분배 없음; 인원수가 보상 개인 금액을 낮추지 않음 |
| 막타/회복/호위 역할 비교 | 자격이 같은 플레이어는 역할이나 막타와 무관하게 기본 완료 보상을 받음 |
| 선택 목표 실패, 작전 성공 | 기본과 첫 완수 보상만 지급; 선택 목표 가산 없음 |
| 실패/철수/사망 | 완료 보상 미지급, 기존 저장 성장 손실 없음 |
| 정산 이벤트 중복 호출 | 같은 출격 보상이 한 번만 반영됨 |
| 저장 직후 정상 재접속 | 모든 성장 축, 해금, 첫 완수 상태가 일치 |
| 저장 도중 종료/디스크 오류 모의 | 이전 유효 프로필 복구 또는 명확한 실패; 새 기본값으로 덮어쓰지 않음 |
| 과거 스키마/잘못된 필드 | 계획된 변환/범위 검증; 확인되지 않은 데이터는 조용히 초기화하지 않음 |
| 레벨/계급/강화 상한 | XP와 지출 가능 자원이 음수/중복 변환 없이 지정한 상한 규칙대로 처리됨 |

멀티플레이 참가자 각자의 Bank가 같은 로비/출격에서 정확히 쓰이고, 저장 이벤트가 동기화/호스트 종료에 어떤 영향을 주는지는 별도 실제 SC2 샘플로 확인해야 합니다. 시험 전에는 “개인별 보상이 저장된다”를 구현 사실로 보고하지 않습니다.

## 관련 결정과 경계

- 성장 레벨/계급/군수 자원/훈련 포인트 상한은 [성장 시스템 통합표](growth-system-matrix.md)를 기준으로 합니다.
- 반복 보상, 첫 완수, 후반 만렙 경제는 [성장·보상 밸런스 초안](growth-economy-balance.md), 반복 횟수는 [성장 시간 계산](pacing-simulation.md)을 기준으로 합니다.
- 작전 기본/선택 목표와 플레이어 수 보상 원칙은 [전투 조우·협동 난도·역할 기여](combat-coop-balance.md)를 따릅니다.
- 이 문서는 저장·정산 설계이며, 현재의 해병 1명·적 3종·작은 아레나·마지막 웨이브 제작 범위를 넓히거나 맵 파일을 바꾸라는 지시가 아닙니다.

# 외부 게임 시스템 대조와 성장·콘텐츠 재설계안

조사일: 2026-10-04  
상태: 기존 해병 성장 RPG 기획을 외부 게임과 대조한 설계 제안. 사용자가 이미 정한 방향과 구분하며, 맵/코드 구현이나 플레이 테스트를 뜻하지 않는다.

## 결론

현재 문서는 성장 메뉴와 장기 콘텐츠 수가 모자라서 빈약한 것이 아니다. 레벨 250, 공적 진급 18계급, 세 갈래 스킬, 50 훈련 포인트, 다섯 성장대/25개 작전, 반복 계약·이벤트·보스까지 큰 설계가 이미 있다. 문제는 이 많은 초안이 실제 반복 플레이 한 바퀴로 묶이지 않았고, 대부분은 아직 맵 코드에 없다는 점이다. 구현 현황은 [2026-10-04 코드·콘텐츠 전수 대조](../implementation-audit-2026-10-04.md)를 기준으로 읽는다.

이번 설계 원칙은 **축을 더 늘리지 말고, 성장축마다 다른 플레이 결정을 주며, 작은 지형에서도 목표 조합으로 사냥이 달라지게 만드는 것**이다. 외부 게임의 규칙을 참고·응용하되 코드·UI·모델을 가져온 것으로 표현하지 않는다. 지금 프로토타입의 바닐라 SC2 자산 및 좁은 구현 경계도 유지한다.

## 권장 플레이 루프

1. **허브:** 한 무기고에서 영구 수치를 정비한다. 플레이어는 건물·이동 장치로 사냥 지역을 고른다. 일반 플레이의 다음 목표를 UI 메뉴 여러 장으로 옮기지 않는다.
2. **사냥터 진입:** 안전한 입구에서 지역을 확인한 뒤, 고정된 지형의 여러 구역 중 계약 목표를 향해 이동한다.
3. **주 계약:** 아래 목표 유형 중 하나. 목표 달성 조건은 처치와 분리한다.
4. **부가 목표:** 가까운 보급품·정찰 지점·위험한 우회 적 중 하나. 원하지 않으면 건너뛴다.
5. **현장 사건:** 정해진 사건 지점/조건에서 최대 하나를 제시한다. 구조·보급대 방어·중계 신호 복구 중 선택하게 한다.
6. **정산과 귀환:** 참가한 각자에게 기본 완료 보상을 주며 기여 행동을 개인 기록으로 남긴다. 전투가 끝난 뒤 귀환하고, 이미 얻은 영구 진행은 실패/복귀로 잃지 않는다.

첫 번째로 만들 콘텐츠 묶음은 신규 지역 수가 아니라 **현재 한 사냥터에서 목표 3종이 실제로 다른 성공 조건을 가지는 한 바퀴**다. 예: (A) 적 무리를 정리해 통신 중계점 작동, (B) 상자 두 곳을 찾아 철수 지점까지 보급, (C) 구조 대상을 위험 구역 밖으로 호위. 세 목표 모두 기존 적 3종과 바닐라 SC2 상호작용을 활용한다. 방어 목표를 만들 때는 실제 Galaxy 이벤트/명령/경로 구현 한계를 확인하고, 이동 호위가 안정적이지 않으면 고정 위치 구조/보호로 단순화한다.

같은 지역 반복에서는 목표 위치 2~3개, 적 편성 2~3개, 부가 목표 2개, 사건 1개를 손으로 조합한다. 최근에 했던 조합이 곧바로 반복되지 않게 하되, 보상과 목표를 출격 전에 읽을 수 있도록 한다. 무작위 생성 자체를 콘텐츠로 착각하지 않는다.

### 보상 규칙

- 적 처치 경험치만으로 성장시키지 않는다. 주 계약 완료는 XP와 공적을 보장하고, 부가 목표는 군수 자원/기록을 보탠다.
- 역할을 선택한 해병이 막타 경쟁을 하지 않도록 치료·보호·구조·목표 상호작용에도 개인 기여를 인정한다. 적 보상 자격은 기여 후 귀환한 플레이어에게 무조건 남기는 대신 활동 구역/행동 참여를 분명히 한다.
- 동급의 사냥·이벤트·도전은 선택 취향에 따른 성장 손해가 크지 않도록 분당 보상 수준을 맞춘다. 낮은 지역은 첫 완수·발견 기록과 귀환 동선의 가치를 갖게 한다.
- 실패해도 이미 얻은 XP·영구 성장은 깎지 않는다. 완수/위험 보너스만 성공 여부에 따라 결정한다.
- 이벤트/계약 갱신을 매일 로그인 조건으로 만들지 않는다. 사용자가 언제든 이어 할 수 있게 고정 지역 풀에서 고른다.

## 성장 구조: 축을 늘리지 않고 역할을 분리

### 1. 레벨 — 매번 조금씩 강해지고 이정표에서 새 행동

초기 상한 **250**과 레벨업 기본 능력 상승은 유지한다. 일부 레벨 이정표에서 액티브·패시브 단계 조건이나 활동을 열어 매번 숫자만 오르는 느낌을 줄인다. 레벨은 지역 입장 제한으로 사용하지 않는다.

기획의 5레벨마다 공용 훈련 포인트 1점은 사용자가 이전에 승인한 방향이므로 유지할 수 있다. 다만 50개의 영구 배분 결정을 모두 초반에 내게 만들지 않는다. 포인트는 안전 허브에서 쓸 수 있게 하고, 새 플레이어가 선택을 유보해도 기본 플레이가 막히지 않도록 다음에 얻을 선택과 노드 효과를 명료하게 보여준다. 성장 초기화는 두지 않는다. 노드 비용/전제는 사용자 선택 없이 숫자만 복잡해지지 않도록 재검산한다.

### 2. 계급 — 커리어 이정표와 상위 선택지 자격

공적을 모아 진급한다. 계급 자체가 레벨의 공격·체력 증가를 다시 복제하지 않도록, 신규 스킬/패시브 단계와 진화 선택 자격을 주로 연다. 18개 계급 표는 이미 제안돼 있으므로 새 등급을 추가하지 않는다. 각 진급을 실제 플레이에서 알아볼 수 있는 영구 기록/명칭 변화와 연결한다.

### 3. 무기고 — 처음에는 이해 가능한 여섯 전투 수치

현재 구현 표에는 기준 차이가 있다. 2026-10-04 전수조사 문서와 프로젝트 README는 네 강화로 적었지만, 직전 구현 작업 요약에는 공격 속도와 체력 재생을 추가해 여섯 강화가 됐다고 되어 있다. 이번에는 사용자 컴퓨터와 로컬 코드를 열지 않았으므로 이를 소스에서 재확인하지 않았다. 다음 소스 대조 때 이 두 기능의 구매·저장·전투 적용을 확인하고 GitHub 현황 문서를 맞춘다. 설계상 기초 강화 후보는 공격, 최대 체력, 이동 속도, 방어력, 공격 속도, 체력 재생 여섯 가지며, 이 여섯 개가 실제 연결돼 있다면 우선 새 기본 스탯을 더하지 않는다.

나중에 스킬이 실제 전투 루프에 들어가면 에너지/스킬 충전, 재사용 대기시간 같은 능력이 필요한지 검토한다. 사거리, 치명타, 상태이상 확률, 저항 여러 종을 한꺼번에 추가하지 않는다. 의미가 겹치거나 화면/밸런스만 복잡해지는 수치는 보류한다. 방어력은 “맞을 때 줄어드는 피해”로 플레이어가 읽을 수 있어야 하며 체력/재생과 함께 피해를 무효에 가깝게 만드는 합산을 막는다.

### 4. 스킬·패시브 — 스탯 숫자가 아닌 역할 선택

기존 세 갈래(돌격·방어·의무/지원)와 3 액티브/6 패시브는 큰 틀을 유지한다. 기본 기술 하나로 시작하고, 이후 투자로 강도보다 사용 방식 또는 팀 기여가 달라지는 진화를 준다. 솔로에서도 각 갈래가 완전히 죽지 않게 한다. 구조/소생 등 구현 복잡도가 큰 지원 기술은 활동 목표와 동시 협동 테스트가 준비된 뒤 연다.

### 5. 작전 기록 — 재화가 아닌 세계 진행

첫 완수·정찰·선택 목표로 지역의 다음 계약이나 숙련 도전을 연다. 별도 화폐, 장비 인벤토리, 일일 퀘스트, 프레스티지를 추가하지 않는다. 파밍은 플레이한 활동을 통해 기존 XP/공적/군수 자원에 계속 기여한다.

## 문서의 과밀과 다음 일괄 작업

현재 README만으로도 성장 곡선, 공적 비용, 강화 가격, 스킬 트리, 성장 체감, 반복 콘텐츠, 다섯 지역 25개 작전이 각각 별도 설계에 존재한다. 더 많은 숫자·콘텐츠 목록을 추가하면 완성도가 아니라 중복만 커질 수 있다. 다음 기획 갱신에서는 세부 문서를 폐기하지 않고, 다음 기준으로 서로 연결해 모순을 걷어내는 것이 낫다.

- 단일 “성장/활동 결정표”를 기준으로 현재 구현 / 사용자 확정 / 제안 / 미검증을 열 단위로 표시한다.
- XP·공적·군수 자원 지급과 소요 시간은 하나의 기준표만 canonical로 삼고, 각 콘텐츠 문서는 그 표를 참조한다.
- 현재 구현 경계(적 3종, 안전 허브/공유 사냥터, 여섯 강화, 개인 Bank, Y 카메라, 비전투 귀환)와 미래 제안(레벨·계급·스킬·작전 목표)을 구분한다.
- 지출 화폐는 기존 세 종류 안에 유지한다. 시스템 수가 많아 보여도 각 시스템의 역할·입구·보상·저장 필드가 분명해야 한다.

## 제작 순서 제안

1. **진행 데이터가 안전한지 먼저 보장:** 기존 코드 조사에서 발견한 군수 상한 초과 및 저장 쓰기가 차단된 상태에서 전투 보상을 얻을 수 있는 경계를 해결/검증한다. 성장을 늘리기 전에 재화 수여·차감·저장 실패가 한 규칙을 쓰게 한다.
2. **현재 여섯 강화 마감:** 표시된 수치, 비용, 실제 적용, 개인 저장·재접속을 각 항목별로 확인한다. 이번 턴에는 게임을 실행하지 않았으며 최근 추가된 속도/재생의 실제 런타임 검증은 별도다.
3. **한 사냥터 목표형 세 활동:** 같은 공간에서 통신/회수/구조 중 세 계약, 선택 부가 목표 하나, 현장 사건 하나를 추가하는 수직 묶음을 만든다. 기여 개인 보상과 1~2인 동시 참여를 함께 검증한다.
4. **영구 레벨 기초:** XP/레벨/이정표/개인 Bank 스키마를 구현하고, 공격·체력만 우선 연결해 레벨 1·중간·상한에서 증가가 정상인지 확인한다. 무기고 강화와 레벨이 같은 성장을 이중 폭증시키지 않게 한다.
5. **계급과 스킬을 하나씩 연결:** 계급 진급, 포인트 투자, 액티브 사용, 저장/재접속을 작은 실제 빌드로 잇고 그 뒤에 패시브/진화와 활동 수를 늘린다.
6. **공간·지역 확장:** 한 지역의 활동 조합과 귀환/길 찾기가 확인된 뒤 다음 구역을 추가한다. 보스·별도 PvP는 현 프로토타입 범위 이후 선택 과제로 둔다.

이는 한 번에 시스템을 잇는 제작 패키지를 제안하며, 매번 1~2줄 기능만 붙였다 떼는 진행을 줄인다. 그래도 데이터 저장, 공유 적, 지형/경로, UI 명령, 카메라 입력은 실패 형태가 달라 한 번의 큰 구현에서 검증 없이 모두 합치지 않는다.

## 아직 입증되지 않은 것

이번 판단은 GitHub 기획 문서·최근 코드 전수조사 문서·외부 공식/제작자 자료를 읽어 대조한 것이다. 로컬 프로젝트/사용자 컴퓨터/게임은 열지 않았다. 캡처·정상 플레이·1~2인 동시 실행·저장 회귀는 수행하지 않았고, UI/UX의 시각 품질, 실제 난이도·재미, 수치 밸런스는 확정하지 않는다. 특히 현재 문서의 만렙 시간, 진급 비용, 훈련 포인트 비용은 여전히 실플레이 검증 전 가정이다.

# 첫 제작 범위와 완료 기준

상태: 기획에서 첫 플레이 가능한 해병 전투 프로토타입으로 넘기기 위한 작업 계약입니다. 아래 범위는 현재 제작 단계에만 적용하며 250레벨 성장, 캠페인, 반개방 사냥터, 세 역할 트리의 출시 확정/구현 승인이 아닙니다.

## 현재 제작 목표

플레이어가 바닐라 SC2 해병 한 명을 조작해 작은 전장에서 기본 적 세 종류와 싸우고, 공격/체력 강화를 시험한 뒤 정해진 마지막 웨이브를 끝내는 작은 플레이 묶음입니다.

| 항목 | 제작 경계 |
|---|---|
| 플레이 캐릭터 | 해병 한 종류. 클래스 선택, 추가 플레이 직업은 없음 |
| 적 | 바닐라 기본 적 세 종류만 사용. 정확한 이름은 staging 카탈로그를 조회한 뒤 정함 |
| 전투 | 기본 이동·공격·피해·사망 및 적 처치. 별도 스킬 트리/보스 페이즈 없음 |
| 성장/소비 | 공격 강화와 체력 강화 두 항목만. 비용 재화는 이 강화만 시험하는 용도로 사용 |
| 공간/진행 | 이동과 교전이 가능한 작은 아레나, 유한한 일반 교전 순서, 명확한 마지막 웨이브 |
| 저장 | 요청된 세션 간 저장을 염두에 두되, 첫 전투가 검증된 다음 공격/체력 강화 단계와 필요한 잔액만 Bank로 저장/복구 시험 |
| 시각 요소 | 바닐라 유닛·액터·UI만 사용. 새 일러스트, 모델, 레이아웃 시안은 없음 |

웨이브는 이 작은 전투 시퀀스의 적 배치/완료 조건입니다. 계급 진급이나 장기 성장의 유일한 수단으로 취급하지 않습니다. 이후 작전/사냥터 보상 경제는 별도 확장 단계입니다.

## 정본 기준과 보존

현재 전달 정본은 `C:\Users\skanya\Documents\StarCraft II\Maps\RPG_Test.SC2Map`입니다. 이번 읽기 전용 MCP 점검에서 정본 메타데이터는 **솔바람 숲 — 모험의 첫날**로 표시됐고, `LibAfterlight.galaxy`에는 여러 클래스, 스킬, 보스 및 이전 RPG 실행 로직이 들어 있습니다. 이 확인은 구성 파일/메타데이터 기준이며 플레이 화면 품질을 평가한 것이 아닙니다.

이전 RPG 기획·리소스·작업본과 기존 MCP dirty workspace는 보존하고 수정하지 않습니다. 새 변경은 현재 정본에서 시작한 별도 MCP staging에서 작게 진행합니다. 제외 기능을 정리하기 전에 기준을 기록하고, 정본 백업과 Candidate가 준비되기 전에는 정본을 덮어쓰지 않습니다. 별도 낡은 `sc2-rpg` 빌드 도구는 새 배포에 사용하지 않습니다.

## 완료 인수 기준

| 구분 | 통과 기준 |
|---|---|
| 시작 | 정상 출격에서 의도한 해병 한 명으로 시작하고, 클래스 선택/이전 영웅 선택 단계 없이 플레이 가능 |
| 조작/전투 | 해병의 이동과 기본 공격이 실제 플레이에서 동작하며, 세 적 종류 각각이 등장·공격·피해·처치 흐름을 가짐 |
| 강화 | 공격 강화가 적 처치 시간/공격 피해를 실제로 바꾸고, 체력 강화가 생존 가능한 피격량을 실제로 바꿈 |
| 구매 유효성 | 잔액 부족 시 구매되지 않고, 강화 구매로 재화가 음수 되지 않으며, 반복 입력 한 번에 두 번 사지지 않음 |
| 교전 흐름 | 일반 웨이브가 순서대로 한 번씩 진행되고, 다음 웨이브/마지막 웨이브 알림이 중복되지 않음 |
| 종료 | 마지막 웨이브 성공과 해병 사망 실패가 서로 구분되고, 종료 후 적/보상/승리 상태가 계속 다시 발동하지 않음 |
| 바닐라 경계 | 추가 직업, 별도 보스 시스템, 인벤토리, 새 일러스트/모델, 복잡한 자체 UI가 추가되지 않음 |
| 저장(후속) | 강화/잔액 변경 후 정상 종료·재실행에서 일치하며, 잘못된 Bank나 저장 실패를 신규 파일로 조용히 덮어쓰지 않음 |

세 적의 정확한 카탈로그 이름, 현재 유닛 능력치, 공격/체력 강화량과 전투 소요시간은 staging 내용을 검사한 뒤 결정합니다. 효과를 알지 못한 채 수치가 맞다고 가정하지 않습니다. 밸런스 수치는 한 번에 하나의 축만 바꾸고 정상 난도의 반복 플레이로 기록합니다.

## 제작 순서

1. **기준선 기록:** 현재 정본의 SHA-256, MCP 읽기 전용 요약, 문서/유닛/트리거/갤럭시 구성과 기존 dirty workspace 목록을 보존합니다. 이전 RPG 작업본은 손대지 않습니다.
2. **작은 staging 변경:** 정본에서 새 writable MCP staging을 열고 한 번에 한 논리 변경만 만듭니다. 첫 기능 변경은 클래스 선택을 제거하고 기본 플레이어를 해병으로 시작시키는 범위로 제한합니다.
3. **staging 검사:** 변경 diff, 데이터/갤럭시 문법 진단, MCP staging 테스트를 확인합니다. 이 MCP 빌드의 갤럭시 검사는 문법만 검사하므로 타입 정확성이나 실제 플레이를 대신하지 않습니다.
4. **전투 수직 묶음:** 해병/기본 적 3종/공격·체력 강화/아레나/마지막 웨이브를 연결합니다. 각 단계에서 적을 추가하거나 다른 UI를 동시에 바꾸지 않습니다.
5. **저장 시험:** 전투 루프가 안정된 뒤 개인 프로필의 필요한 최소 값만 Bank에 저장해 솔로 종료·재실행부터 확인합니다. 멀티 저장은 별도 테스트 전에는 통과했다고 말하지 않습니다.
6. **Candidate 검증 및 설치:** staging을 Candidate로 패킹하고, 정본 SHA를 확인해 백업한 다음 `marine-growing/pipeline.mjs`의 배포 흐름으로 원자 설치합니다. MCP에서 새 정본을 다시 열어 검사합니다.
7. **실게임 시험/기록:** 실행 전 정본과 설치 관리 런타임 맵의 SHA-256 일치, 실행 인자, PID/로그를 기록합니다. 정상 플레이로 성공/실패 흐름을 시험하고, 테스트 뒤 양쪽 해시를 다시 비교합니다. 외부 teleport/강제 처치/가속 체크포인트는 정상 플레이 완료로 기록하지 않습니다.
8. **시각 캡처:** 시각 변경이 있거나 결과를 확인해야 할 때 실제 게임 Print Screen을 `capture.mjs`/computer-use Sky 경로로 캡처하고 `latest.png`와 최대 5개 checkpoint를 갱신합니다. 실제 이미지를 다시 읽어 평가하며 검은 화면 감지만으로 통과 판정하지 않습니다.

MCP 실행 체크가 성공해도 사람의 일반 플레이에서 시간·난도·조작감·재미가 확인된 것은 아닙니다. 이러한 평가는 사람이 정상 속도로 플레이한 뒤 별도 기록합니다.

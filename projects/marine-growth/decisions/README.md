# 결정 기록

이 디렉터리는 해병 성장 RPG에 대해 사용자와 합의된 기획만 기록합니다. 다른 모드의 결정과는 분리합니다. 조사에서 발견한 기능은 합의되기 전까지 결정이 아닙니다.

## 사용자가 제시한 방향 (2026-10-03)

1. 스타크래프트 II만 대상으로 조사하고 기획합니다.
2. 해병의 성장 게임이며 계급은 주요 성장 축 중 하나입니다.
3. 계급 진급을 웨이브 클리어에 매번 고정하지 않습니다. 웨이브 외의 진행 방식을 조사합니다.
4. 난도는 지나치게 높이지 않습니다.
5. 협동을 중심으로 하고, PvP를 넣더라도 선택형으로 둡니다.
6. 스킬·시스템·콘텐츠가 풍부한 방향을 선호하지만 첫 버전 범위는 미정입니다.
7. Codex는 새 UI/UX와 바닐라 외 모델을 임의로 만들지 않습니다. 필요하면 외부 사례와 출처부터 조사합니다.
8. 스테이지 맵을 선택해 순찰/탐험, 보스전, 이벤트를 플레이하는 방향을 검토합니다. 혼자 또는 함께 출격할 수 있게 합니다.
9. 계급 진급은 재화를 사용하며, 계급 외에도 레벨업·강화·스킬·패시브 등 여러 성장 방식을 원합니다.
10. 한 해병 안에서 돌격/방어/회복·지원처럼 성장 갈래를 만드는 방향을 검토합니다.
11. 해병 레벨·스킬·패시브·강화 등 키우기 성장은 스테이지 종료 때 초기화하지 않습니다.
12. 레벨업은 기본 능력치 증가와 함께 제한 해제나 새 효과 등 추가 보상을 주는 방향을 검토합니다.
13. 레벨업마다 기본 능력치가 영구 상승하고, 정해진 레벨에서 새 효과/기능을 해금합니다.
14. 스킬 포인트와 패시브 포인트를 따로 나누지 않습니다. 두 갈래에 모두 쓸 수 있는 공용 훈련 포인트 하나를 사용합니다.
15. 초기 해병 만렙은 250으로 둡니다. (2026-10-03 사용자 확인)
16. 레벨·계급·재화·스킬·패시브·해금은 출격 사이에도 계속 보존합니다. SC2 Bank를 우선 저장 방식으로 검증합니다. PC 간 자동 동기화는 보장하지 않습니다.
17. 시작부터 전투를 강제하지 않습니다. 안전한 마을/메인 허브에서 정비하고 스테이지·탐험·사냥·보스 등의 활동에 들어가는 흐름을 둡니다. 현재 제작에는 테란 전초기지와 공간 이동 장치를 통한 공유 사냥터 입장·귀환을 적용합니다. (2026-10-03)
18. 단계별 출격 버튼·웨이브 중심 제작을 공유 사냥터 방향으로 수정합니다. 실제 시설에서 강화하고 이동 장치에 걸어가 입장·귀환합니다. 개인별 입장과 협동을 함께 고려하며 공격·체력에 이동속도·방어력을 추가하고 강화 종류를 확장합니다. 공개 모드의 코드와 시스템을 실제로 조사하면서 작업합니다. 현재 구현·검증 경계는 [공유 사냥터 기준](../design/spatial-hub-and-hunting-prototype.md)에 기록합니다. (2026-10-03 사용자 수정)

## 위임받아 정한 현재 기획 방향

- 사용자가 사냥터 구조 선택을 맡겨, 캠페인은 수제 핵심 작전으로 진행하고 반복 성장은 지역별 반개방 사냥터에서 하는 구조를 채택해 세부 기획을 이어갑니다. MMO식 공개 영구 월드는 전제하지 않습니다.
- 사냥터 외에도 보스 사냥, 현장 이벤트, 협동 도전, 탐험/발견을 둡니다. 각 콘텐츠가 XP만 똑같이 주는 대신 계급·군수 자원·스킬/지역 해금에 서로 다른 이유를 제공합니다.
- 사용자는 세부 수치·스테이지·성장·밸런스 작업을 Codex에게 위임했습니다. 레벨 250, XP/공적/군수 자원·훈련 포인트 역할 분리, 수제 지역 5곳/핵심 작전 25개를 작업안으로 구체화했습니다.
- XP/분은 후반 활동이 더 높도록 설계하되 6~8배 차이를 한 사냥터가 독점하지 않게 합니다. 현재 수치 계산은 첫 완수 25개와 후반 보상 시 만렙까지 136~159회/약 27~32시간을 추정하지만 플레이테스트 전 작업안입니다.
- 영구 성장, 훈련 투자, 계급, 공격/체력 강화는 되돌리거나 초기화하지 않는 방향으로 기획합니다. 계급은 공적, 공격/체력 강화는 군수 자원을 씁니다.
- 지역 해금은 작전 기록, 계급은 공적, 스킬/패시브의 투자 깊이는 계급+훈련 포인트로 분리합니다. 추천 레벨은 진입 제한이 아닙니다.
- 상세 콘텐츠·수치·보상안은 실제 밸런스 검증 전입니다. 현재 제작 범위는 사용자 수정 18번을 반영하며, 장기 기획 전체가 구현된 것으로 취급하지 않습니다.

## 검증 전인 제안과 사용자 협의가 필요한 방향 결정

- XP 증가량, 계급 총 공적 20,000, 공격/체력 최대 강화 비용 15,000과 레벨당 공격/체력 증가식은 계산에 맞춘 검증 전 제안입니다. 세부 밸런스는 Codex가 작업하고 정상 플레이 데이터로 조정합니다.
- 일일 활동시간/첫 완료 목표 달성률은 가정입니다. 만렙 목표 시간은 정상 플레이에서 활동 시간·보상 획득률을 기록한 뒤 조정해야 합니다.
- 선택형 PvP를 실제 출시 범위에 포함할지 여부는 협동/성장 구조가 검증된 뒤 큰 방향 결정이 필요합니다.
- 사용자가 별도로 원하는 세계관/서사나 특정 스타크래프트 세력을 중심으로 하는지 아직 지정하지 않았습니다. 이 선택이 지역 구성/아트 자산을 크게 바꾸는 단계가 오면 쟁점과 선택지를 제시합니다.

세부 수치나 플레이테스트 전 제안은 사용자 선택이 필요한 큰 방향으로 취급하지 않습니다. 핵심 컨셉·세계관·출시 모드 범위가 바뀌는 결정만 사용자와 상의합니다.

## 2026-10-04 추가 결정

- 모든 공통 강화는 한 무기고에서 구매합니다. 접촉으로 자동 차감하지 않고 효과·가격을 보고 클릭합니다.
- 사냥터는 적 한 종류당 한 마리 배치에서 넓은 지역과 여러 무리로 바꿉니다. 입구는 안전하게 배우고 안쪽 위험 구역을 선택합니다.
- 게임 화면에는 개발 로그·구현 설명·불필요한 시작 안내·정상 저장 상태를 넣지 않습니다. 건물 이름과 효과·가격·보상·필요한 오류만 표시합니다.
- 허브와 사냥터를 단절하며 자기 해병 카메라를 기본으로, Y로 해제/재고정합니다.

- 사용자가 직접 프로토타입을 테스트한 뒤 밸런스가 괜찮다고 평가했다. 해당 수치와 비용을 유지한다. 기본 명령창 귀환(B)/8초 전투 제한,192×192확장과 북부 사냥터·월드 포탈을 실제 구현했다. 깊은 동선·실제2인 검증은 남았다.
- 매 작업마다 제작자 코드/방식 또는 실제 장면을 확인하고 재사용·응용·미검증 범위를 기록한다. 읽기만 한 코드나 이미지를 가져왔다고 표현하지 않는다.

## 2026-10-04 최신 작업 우선순위

- 사용자 요청: 밸런스보다 콘텐츠·디자인·UI/UX·재미 요소의 조사와 구현을 우선한다. 앞의 Codex 밸런스 위임 기록보다 이 요청을 우선하며 사용자가 나중에 실제 밸런스를 조정한다. Codex는 상한·오류 등 대략적인 수치만 확인한다.
- 기본 자산으로 포탈 가시성,보급품6곳의 개인 영구 회수,감시탑3곳을 구현했다. 신규 클래스·보스·인벤토리·복잡한UI는 현재 범위 밖이다.
- 기존 개인 성장을 보존해 저장Schema1→2를 검증했다. 사람의 재미는 실제 정상 플레이 평가 전이며 자동 캡처/입력 검증으로 단정하지 않는다. 구현·출처·남은 검증은 [탐험 기록](../design/exploration-and-world-ux.md)에 있다.

- 다음 지형 배치에서 Tristram실제 장면을 다시 보고 기본SC2길·포장·수목만 적용했다. 외곽 밝은 공터/북부 낡은 포장으로 구분하며 기존 전투 수치는 유지한다. 실제 북부 첫 탑·외곽 첫 회수만 확인했으며 나머지 구역의 접근은 미검증이다. [갈래길·지역 바닥 기록](../design/landmark-routes-and-region-surfaces.md).


## 2026-10-07 검증 방식과 적정 난도

- Codex는 밸런스 플레이 테스트나 재미·조작 체감 테스트를 하지 않습니다. 밸런스와 재미 방향은 외부 모드·게임의 제작자 코드와 공개 자료를 조사해 비교하고, 기본 난도는 지나치게 빡세지 않은 방향으로 제안합니다.
- 개발 중 검증은 코드 경계/회귀 검사로 빠르게 합니다. 스타크래프트 실행은 로드·스크립트 오류·UI 캡처·명확한 런타임 버그 확인에 한정하고, 이런 확인을 일반 플레이나 난도 검증으로 표현하지 않습니다.
- UI 캡처가 필요하면 실제 게임 Print Screen을 우회 수집하고 이미지를 직접 읽습니다. 좌표 입력은 최신 Sky 창 캡처 ID를 얻은 뒤 그 관찰에 맞춰 수행합니다. Sky 프레임 캡처가 실패하면 좌표 결과를 기능 결함의 증거로 단정하지 않습니다.
- 현재 보통 난도 원칙은 외부 비교 문서 [외부 콘텐츠 구조와 난이도 가이드](../design/field-route-and-ux-refinement.md)에 기록했습니다. 새 적/보스/복잡한 UI는 합의된 프로토타입 범위를 넓히지 않습니다.

## 2026-10-07 사용자 추가 지시 — 매 대화·콘텐츠 작업에 적용

- 외부 모드 참고는 기술 시스템이나 코드만이 아니다. 실제 플레이 방식과 콘텐츠, 지역 규모·구성, 사냥 동선·지역 이동과 해금, 적 종류와 무리, 임무·이벤트 흐름까지 조사해 게임에 가져오고 융합한다.
- 사냥터·콘텐츠를 실질적으로 바꾸기 전에는 관련된 실제 SC2 모드 두 가지 이상을 제작자 자료·공개 코드·실제 장면으로 대조한다. 구체적으로 무엇을 참고했고 무엇을 구현·검증했는지 기록한다. 코드 함수 몇 개 열어본 걸 전체 게임 방식 조사라고 부르지 않는다.
- 모든 대화 시작 때 프로젝트 README, 이 결정 기록, 최신 회의 기록, 최신 레벨 1~100 구현 기록, 그리고 당면 작업의 관련 설계·조사 문서를 먼저 읽는다. 짧은 후속 대화도 예외가 아니다.
- 모든 대화의 마지막 인수인계에는 다음 대화도 같은 기획 문서를 먼저 다시 읽어야 한다고 명시한다.
- 2026-10-07 시점 프로토타입의 사냥 콘텐츠는 단일 맵의 외곽·북부 두 구역과 세 적 유형이다. 넓고 구분된 다지역 사냥 동선·지역 진행·다음 사냥터 이동은 완료되지 않았다. 완료 범위를 과장하지 않는다.

# StarCraft II 맵 진행 데이터 저장 조사

조사일: 2026-10-03. 해병 성장 RPG의 레벨·계급·재화·스테이지 진행을 게임 종료 이후에도 보존할 수 있는지 확인합니다.

## 결론

**가능합니다.** StarCraft II Galaxy Editor에는 `Bank` 기능이 있어 플레이어별 파일에 데이터를 읽고 쓰고, 다음 플레이 때 다시 불러올 수 있습니다. Blizzard의 1.1.0 패치 노트는 Banks가 경험치, 습득 능력, 아이템을 저장·복원한다고 명시합니다. 편집기 가이드에는 섹션/키/값 구조와 `Open Bank`, `Store Data`, `Save Bank`, `Wait For Bank`, `Preload Bank` 동작이 설명되어 있습니다.

- [Blizzard 1.1.0 패치 노트: Banks의 XP·능력·아이템 저장](https://news.blizzard.com/en-gb/article/9993888/patch-1-1-0-now-live)
- [StarCraft II Editor Banks 가이드](https://s2editor-guides.readthedocs.io/New_Tutorials/03_Trigger_Editor/051_Banks/)
- [Blizzard 4.1.4 패치 노트: BankBackup / BankRestore 추가](https://news.blizzard.com/en-us/article/21313391/starcraft-4-1-4-patch-notes)

## 무엇을 저장할 수 있나

은행은 플레이어별 저장 파일에 섹션과 키를 만들어 유형이 있는 값을 보존하는 구조입니다. 우리 게임에서는 다음을 작은 키-값 묶음으로 저장할 수 있습니다.

| 은행 섹션 예시 | 저장할 값 예시 |
|---|---|
| Profile | 저장 형식 버전, 해병 레벨, 현재 경험치 |
| Career | 계급, 공적, 누적 작전 수 |
| Growth | 군수 자원, 영구 강화 단계, 훈련 포인트 사용 상태, 스킬/패시브 진화 |
| Unlocks | 완료한 지역/작전, 선택 목표와 첫 발견 기록 |

Galaxy 쪽에서는 은행 열기/읽기/값 쓰기/저장 동작을 사용합니다. 이름과 플레이어 기준으로 불러온 뒤 값을 바꾸고 `BankSave`로 저장하는 일반적인 패턴입니다. 시작 시 읽기가 끝나기 전에 진행 데이터를 사용하지 않도록 `Wait For Bank` 흐름도 확인해야 합니다.

## 중요한 한계

- **저장과 서버 동기화는 다릅니다.** Blizzard 캠페인 진행은 Battle.net 프로필 클라우드 저장을 쓴다고 별도로 안내했지만, Arcade Bank 가이드는 플레이어의 로컬 저장 폴더를 안내합니다. 따라서 이 해병 맵의 Bank가 다른 PC로 자동 이전된다고 약속하면 안 됩니다. 기술 지원 포럼의 사용자 사례도 새 PC에서 Arcade 진행을 옮길 때 기존 Bank 폴더를 복사해야 했다고 보고합니다.
- [Blizzard: 공식 캠페인 진행은 Battle.net 프로필에 저장](https://news.blizzard.com/en-us/article/601771/campaigning-on-the-go)
- [Blizzard SC2 기술 지원 포럼: Arcade Bank 폴더 이전 사례](https://us.forums.blizzard.com/en/sc2/t/how-to-load-arcade-map-data-into-another-computer/28905)
- 서명 기능이나 백업 네이티브가 있어도 플레이어 로컬 진행 파일이 계정 서버의 권위 있는 기록과 같아지는 것은 아닙니다. 이 기획은 PvP 성적이나 현금 가치가 있는 재화를 Bank의 변조 불가능성에 의존시키지 않습니다.
- 사용자가 폴더를 삭제하거나 PC를 바꾸면 진행이 사라질 수 있으므로, 지속 성장 게임에서 저장 손실 테스트와 백업/복원 경로가 중요합니다.
- 여러 Arcade 맵을 캠페인처럼 연결할 경우 맵 전환 지원과 뱅크 네임스페이스/사용자 식별이 함께 동작하는지 별도 검증해야 합니다. Blizzard는 5.0에서 동일 제작자의 공개 맵 사이 로비 전환을 지원했지만, 이는 계정 전체 저장소를 제공한다는 뜻은 아닙니다.
- [Blizzard 5.0 패치 노트: 공개 커스텀 캠페인의 맵 간 전환](https://news.blizzard.com/en-us/article/23482838/starcraft-ii-5-0-patch-notes)

## 해병 성장 RPG 저장 설계 권장안

1. **캐릭터 하나의 영구 성장 프로필**을 Bank 하나에 저장합니다. 경험치/레벨, 계급/공적, 군수 자원, 기본 강화, 스킬/패시브, 해금 기록을 스테이지 선택 화면부터 불러옵니다.
2. 스테이지 시작 전에 Bank를 읽고 준비 완료를 확인합니다. 로드 실패/빈 데이터면 새 해병 기본값으로 시작하되 기존 파일을 바로 덮어쓰지 않습니다.
3. 작전 완수 또는 진급/강화 구매 같은 중요한 영구 변화 뒤에 저장합니다. 적 처치 하나마다 저장하지 않습니다.
4. 저장 스키마 버전을 같이 기록합니다. 새 패치에서 키가 추가/이름 변경돼도 이전 프로필을 읽고 기본값을 채우는 변환 경로가 필요합니다.
5. 레벨·공적·군수 자원·강화 단계는 읽을 때 범위를 확인합니다. 없거나 잘못된 키가 있다고 진행 전체를 초기화하지 말고 복구/기본값 처리를 합니다.
6. BankBackup/BankRestore 지원을 보더라도 실제 Arcade 맵에서 저장 실패·강제 종료·이전 데이터 복구를 테스트합니다. 기능 이름만으로 안전성을 가정하지 않습니다.
7. 첫 버전의 보장 문구는 **같은 SC2 사용자 환경의 다음 세션에서도 진행을 불러오는 것**으로 제한합니다. PC 간 자동 이전과 온라인 계정 동기화는 별도 기술 검증 전까지 지원한다고 약속하지 않습니다.

저장은 가능하지만, 그것만으로 계정 간/기기 간 클라우드 진행이 보장되는 것은 아닙니다. 맵 제작 샘플의 실제 은행 로드/저장/재접속 테스트가 필요하며, 사용자에게 보이는 UI를 새로 그릴 이유는 없습니다.
